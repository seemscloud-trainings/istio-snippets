# Istio Snippets

This repository contains small, independent Istio training examples. Follow the sibling istio-setup documentation style: README.md is a links-only index; topic pages start directly with short preparation/example headings. Use English for descriptions and diagrams. ServiceEntry variants are alternatives for the same host, not a combined installation. Preserve the current branch and unrelated changes; commit/push only when requested.

service-entry/*.yaml are the canonical copyable manifests. README.service-entry.md contains only example headings, YAML blocks and PNGs from images/service-entry/. scripts/render_service_entry.py renders the five diagrams and regenerates the topic page from these manifests. Each Pod shows a Container running plain curl http://wp.pl or curl https://wp.pl, its resolved IP, Envoy and the upstream socket. Above Envoy, a ServiceEntry block lists only relevant inputs (hosts, resolution, addresses/endpoints or port translation); Envoy shows the effective host-to-IP mapping instead of endpoints/configuration fields. Traffic arrows use HTTP/HTTPS, including HTTP-to-HTTPS origination; TLS remains only in actual configuration field names. Resolver labels must be just DNS. Do not add footers, explanatory paragraphs, callout cards, legends or repeated titles. The offline Pillow/PyYAML renderer uses illustrative RFC 5737 DNS answers: wp.pl = 198.51.100.10 and backend.wp.pl = 198.51.100.20; these are not real DNS measurements. Assume sidecar mode with DNS capture disabled. For NONE, plain curl receives the DNS IP, which does not match the supplied addresses; show the explicitly labeled ALLOW_ANY passthrough case, never fabricate DNS rewriting or use --resolve. STATIC selects the configured destination, and TLS origination uses targetPort to change ports.

Regenerate with python3 scripts/render_service_entry.py using an existing Python environment with Pillow and PyYAML; do not install dependencies without authorization. PNG output is reproducible with the same Pillow and fonts (Arial on macOS, DejaVu Sans fallback on Linux); --check compares generated Markdown and image pixels without writing files. Review every rendered image, parse the YAML, validate against locally available Istio schemas when possible, and review Git diff/status before committing. Do not apply manifests, start services, or contact example endpoints during verification. The documentation describes intended routing, not a verified live environment.
