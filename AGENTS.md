# Istio Snippets

This repository contains small, independent Istio training examples. Follow the sibling istio-setup documentation style: README.md is a links-only index; topic pages start directly with short preparation/example headings. Use English for descriptions and diagrams. Always use wp.pl for example public domains, including the illustrative JWT issuer/JWKS; do not use example.com or example.test. Kubernetes Service DNS names remain real backend identifiers. Sidecar examples live in sidecar/; PeerAuthentication plus AuthorizationPolicy in peer-authorization/; JWT plus AuthorizationPolicy in request-authorization/. Each has a root README topic page with three YAML examples and a diagram per example. These are alternative configurations, not cumulative installations. ServiceEntry variants are alternatives for the same host, not a combined installation. Preserve the current branch and unrelated changes; commit/push only when requested.

service-entry/*.yaml are the canonical copyable manifests. README.service-entry.md contains only example headings, YAML blocks and PNGs from images/service-entry/. scripts/render_service_entry.py renders the five diagrams and regenerates the topic page from these manifests. Each Pod shows a Container running plain curl http://wp.pl or curl https://wp.pl, its resolved IP, Envoy and the upstream socket. Above Envoy, a ServiceEntry block lists only relevant inputs (hosts, resolution, addresses/endpoints or port translation); Envoy shows the effective host-to-IP mapping instead of endpoints/configuration fields. ServiceEntry traffic arrows use HTTP/HTTPS, including HTTP-to-HTTPS origination; TLS remains only in actual configuration field names. Every illustrated Pod has an Istio sidecar. Omit redundant injection labels and never show a no-sidecar scenario. Plaintext security examples use an explicit client-scoped DestinationRule with tls.mode DISABLE and workloadSelector app=plain; the source Envoy returns 503 when STRICT rejects its upstream connection. Security and Sidecar diagrams explicitly distinguish HTTP from mTLS, and show where Envoy rejects a request before the API is reached. Show DNS only in diagrams whose illustrated snippet includes a ServiceEntry. Omit DNS boxes and lookup labels from VirtualService-only and Sidecar examples. The VirtualService Host + subsets setup contains a ServiceEntry and may show DNS. Resolver labels must be just DNS. Public examples must contain only short headings, comment-free YAML and diagrams. Every YAML array with exactly one element must use flow brackets, including arrays of objects: hosts: [wp.pl] and ports: [{number: 443, name: https, protocol: TLS}]. Apply this to canonical manifests and every embedded README block. All renderers use scripts/yaml_style.py; preserve parsed values while formatting. Explain behavior through diagram flows; never add explanatory YAML comments, prose, footers, callout cards or legends. Keep setup assumptions in this AGENTS.md. The offline Pillow/PyYAML renderer uses illustrative RFC 5737 DNS answers: wp.pl = 198.51.100.10 and backend.wp.pl = 198.51.100.20; these are not real DNS measurements. Assume sidecar mode with DNS capture disabled. For NONE, compare the curl DNS IP with the listed addresses and show that this ServiceEntry is not used when they differ. Draw separate outbound-policy outcomes: ALLOW_ANY keeps curl's original destination, REGISTRY_ONLY blocks the connection. Do not use unexplained no-IP-match shorthand, fabricate DNS rewriting or use --resolve. Name this example Original destination, not Service Translation. DNS endpoint overrides must explicitly show the different backend hostname's resolved IP beside that endpoint in the ServiceEntry block. STATIC selects the configured destination, and TLS origination uses targetPort to change ports.

Trouble response codes, probabilities and delays are scenario assumptions from source comments, not measured responses; rate limits are per inbound Envoy, pool limits per client Envoy, retries may stop at the overall timeout, and outlier diagrams assume at least two Pods and the consecutive-error threshold reached. Public page format stays heading/YAML/diagram only. Review every rendered image, parse the YAML, validate against locally available Istio schemas when possible, and review Git diff/status before committing.
